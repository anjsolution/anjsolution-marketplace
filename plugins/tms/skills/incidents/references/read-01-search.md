# 장애 조회 진행 방법

## 질문을 검색 조건으로 바꾸기

- 특정 터널의 장애를 찾는다면 명칭·소속으로 대상을 확정한다. 동명 터널이 있으면 catalog 스킬이나
  제공된 조회 도구로 구분하고 임의로 한 곳을 선택하지 않는다.
- "서버 교체한 장애"처럼 조치 내용을 찾는 질문은 현재 도구가 제공하는 구조화 필터를 우선한다.
  조치 경위·후속 계획처럼 필터로 표현되지 않는 내용은 keyword로 보완한다.
- "현장 대응" 여부는 메모에 등장하는 '현장'이라는 단어보다 구조화된 접근 값을 기준으로 판단한다.
  직원 출동인지 지사 인원의 자체 조치인지 본문만으로 단정하지 않는다.

## 요약에서 필요한 상세로 좁히기

먼저 `search_incidents`의 요약으로 대상과 규모를 확인한다. 사용자가 대응 과정이나 조치 원인을
묻는 경우에만 해당 범위의 상세 이력을 조회한다. 상세에서도 이력이 잘렸는지·더 조회할 수 있는지
응답의 페이지 정보를 확인하고, 조회한 일부를 전체 이력처럼 설명하지 않는다.

장애 응답의 대상 정보에 본부·지사·노선이 있으면 그대로 사용한다. 같은 정보를 얻기 위해
catalog와 다시 조인하지 않는다. 대상이 여러 곳이면 실제 대상별로 유지한다.
응답에 없는 위치·담당자·원인은 추정하지 않는다.

## 결과 안내

목록은 장애코드·대상·접수일시·상태·핵심 내용 위주로 제시한다. 질문에 필요한 경우 대응·조치
내용을 덧붙인다. 내부 ID는 후속 도구 호출을 위해 유지하되 기본 안내 표에서는 생략한다.
검색 결과가 없으면 "해당 조건에서 찾지 못함"으로 안내한다. 권한·연결 오류를 0건으로 해석하지 않는다.
