# 장애 history 엑셀과 TMS 비교·특이사항 보고

사내 "장애 history" 엑셀(.xlsm)과 TMS 장애 데이터를 비교해 차이를 **보고**한다.
엑셀 행을 TMS에 일괄 신규 등록하는 기능은 현재 보류 상태다. 비교 결과에서 미등록 행을 찾았더라도
등록을 시작하지 않는다. 사용자가 특정 건의 등록을 따로 요청하면 해당 쓰기 문서를 따른다.

## 도구

[엑셀 비교 스크립트](../scripts/excel_history.py)를 쓴다. Python 3와 openpyxl이 필요하다.
incidents 스킬 폴더 기준 `python scripts/excel_history.py`로 실행하고, 작업 디렉터리가 다르면
설치된 스킬의 절대경로를 쓴다. 출력은 JSON이다.

| 명령 | 용도 |
|---|---|
| `pending <엑셀> --remote <조회결과.json>` | 원격 마지막 접수번호 이후의 엑셀 행, 중복 의심, 대응·조치 추가분 |
| `locate <엑셀> <접수번호…>` | 접수번호를 엑셀 접수일별로 묶은 날짜 조회 계획 |
| `check <엑셀> <접수번호…> --remote <날짜별조회.json>` | 번호별 있음·없음·중복 의심 판정 |
| `extract <엑셀> <접수번호…>` | 접수번호별 장애·대응·조치 초안과 검토 항목 |
| `fix <엑셀> <접수번호> --code/--action <값>` | 장애코드(D열)·조치코드(K열) 셀 수정 |

## 비교 순서

1. `search_incidents`로 최근 장애를 조회한다. 먼 과거는 비교하지 않는다. 응답을 작업 파일로 저장한다.
   최근 결과에 접수번호가 있는 장애가 없으면 다음 페이지를 더 조회한다.
2. `pending`에 엑셀과 저장한 조회 결과를 넣는다. 조회 응답에 접수번호 필드가 없는 서버라면
   사용자에게 마지막 접수번호를 확인해 `--after`로 지정한다.
3. `pending`이 "엑셀에만 있음"으로 낸 번호는 `locate`·`check`로 최종 확인한다. 엑셀 접수번호 순서가
   접수일 순서와 다를 수 있어, 최근 조회에 없던 번호도 원격에 있을 수 있다.
4. `extract`로 필요한 건의 초안을 확인한다. 대상은 본부·터널명 원문이며 ID로 바꾸지 않았다.

## 특정 번호의 존재 확인

"1707번 들어가 있어?"처럼 특정·과거 번호를 물으면 전체 목록을 넘기지 않는다. 조회 도구에는 접수번호
필터가 없지만 접수일 필터가 있으므로 날짜로 좁힌다.

1. `locate`로 번호를 엑셀 접수일별로 묶는다.
2. 날짜마다 `search_incidents`를 `from`·`to`를 같은 날로 호출하고, 응답을 배열로 모아 저장한다.
   `다음페이지있음`이면 다음 페이지도 받는다.
3. `check`로 번호별 판정을 받는다. "있음"은 장애코드와 함께, "중복 의심"은 접수번호 없이 같은 시각에
   등록된 원격 장애와 함께 보고한다. 엑셀 접수일이 잘못 적혔으면 "없음"이 나올 수 있으므로 앞뒤 날짜를
   추가 조회할지 사용자에게 묻는다.

## 보고할 특이사항

결과를 아래 순서로 요약한다. 항목이 없으면 "없음"으로 적는다.

- **기준:** 원격 마지막 접수번호와 그 장애코드·접수일시, 엑셀 마지막 접수번호.
- **엑셀에만 있는 장애:** 접수번호·접수일시·터널명·내용 요약. 등록 가능과 수정 필요를 나눈다.
- **수정 필요:** 행마다 열과 사유(예: "K열 조치코드 'OXBS'의 method 해석 불가"). 올바른 값을
  추측해 채우지 않는다. 원인·조치 문장을 근거로 후보를 제안할 수는 있으나 제안임을 밝힌다.
- **중복 의심:** 접수번호 없이 원격에 등록된 장애와 같은 날·같은 시각의 엑셀 행. 같은 장애인지
  판단은 사용자에게 맡긴다.
- **대응·조치 추가분:** 조회 범위 안의 장애 중 엑셀의 대응 줄 수가 원격 대응기록수보다 많거나,
  엑셀에는 조치가 있는데 원격은 조치완료가 아닌 건.
- **결번:** 기준 이후 엑셀 접수번호가 비어 있는 번호.

## 엑셀 수정

사용자가 고칠 값을 명시한 경우에만 `fix`를 실행한다. 스크립트는 값을 검증하고, 원본 옆에
`.bak-날짜` 백업을 만든 뒤 해당 셀만 바꾼다. 엑셀에서 파일이 열려 있으면 거부하므로 닫아 달라고
안내한다. 엑셀 파일을 openpyxl 등으로 통째로 다시 저장하지 않는다. 통계 시트의 차트·매크로가
손상될 수 있다. 수정 후 `pending`을 다시 실행해 해당 행이 수정 필요에서 빠졌는지 확인한다.
