# 신규 장애 등록 진행 방법

[쓰기 공통 절차](write-01-common.md)를 함께 따른다. 현재 등록 도구는 `create_incident`다.
필드명·필수값·허용 enum은 실행 시 도구 스키마를 확인한다. 읽기 필터의 한글 라벨 허용을
쓰기 입력에도 그대로 적용할 수 있다고 가정하지 않는다.

## 등록 의도와 대상 확정

"서버 다운 장애를 등록해줘"는 신규 장애 등록이다. "기존 장애에 출동 내용을 추가해줘"는
대응 기록 추가이므로 신규 장애로 대신 등록하지 않는다. 대응·조치 쓰기는 아직 지원하지 않는다.

명칭으로 대상을 조회하고 소속·터널코드 등으로 동일 대상을 확인한다. 현재 도구 입력에서
요구하는 ID는 조회 응답에서 가져온다. 동명 대상이나 여러 후보가 있으면 필요한 구분만 질문한다.
조회에서 필요한 ID를 얻지 못하면 임의 숫자를 만들거나 코드에서 계산하지 말고 부족한 정보를 알린다.

## 내용 준비와 전송

사용자가 제공한 현상·요청 내용을 바탕으로 분류와 메모를 작성한다. "서버 교체 필요"를
"서버 교체 완료"로 바꾸지 않는다. 명확히 요청하고 충분한 정보를 준 등록을 매번 재승인받을
필요는 없으며, 대상·내용이 불명확한 경우에만 필요한 질문을 한다.

사용자가 접수 시각을 지정했다면 시간대를 확인해 KST 입력으로 전달한다. 현재 접수 시각을
뜻하고 별도 시각을 지정하지 않았다면 선택 입력을 생략해 서버 시각을 사용한다.
시계 확인 없이 현재 시각을 추측하거나 UTC 시각에 KST 표기만 붙이지 않는다.

공통 절차로 UUID·입력을 기록한 뒤 도구를 호출한다. 접수자·작성자를 지정하려고 인증 정보나
지원하지 않는 필드를 추가하지 않는다. 장애코드도 직접 만들지 않고 서버의 등록 결과를 사용한다.

## 완료 안내와 조회 확인

성공 결과를 작업 기록에 저장하고 장애코드·대상·접수일시·상태·메모 요약을 안내한다.
사용자가 반영 확인을 원하면 반환된 전체 장애코드로 조회하고 코드가 정확히 일치하는 결과를 확인한다.
조회 결과가 바로 보이지 않아도 등록을 새 UUID로 다시 실행하지 않는다.
