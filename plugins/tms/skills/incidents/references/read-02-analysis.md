# 장애 통계와 이력 분석 진행 방법

## 통계 도구로 답할 수 있는 질문

질문의 비교 대상과 기간을 정하고 `incident_stats`에서 제공하는 필터·집계 축을 조합한다.
예를 들어 "서버 교체를 위해 현장 대응한 장애가 어느 본부에 많은가"는 조치 방법·접근을
필터로 두고 본부별로 집계한다. 허용되는 필드와 값은 현재 도구 스키마에서 확인한다.

결과 설명에는 실제 집계 기간과 집계 기준을 붙인다. 여러 대상에 걸친 장애의 그룹별 합계는
중복을 포함할 수 있으므로 도구가 반환한 전체 건수와 구분한다. 미지정 그룹도 결과에 포함한다.

## 통계 도구에 없는 축을 분석할 때

대응자·소요시간·본문 패턴처럼 현재 집계 축에 없는 질문은 다음 순서로 처리한다.

1. 기간·대상·분류 등으로 범위를 좁히고 요약의 총건수와 페이지 수를 확인한다.
2. 필요한 장애의 상세 이력을 조회한다. 모든 상세 페이지를 받지 못했다면 분석 범위를 기록한다.
3. 양이 많으면 필요한 조회 결과를 로컬 작업 파일에 저장하고 코드로 집계한다.
4. 장애 건수와 대응 기록 건수를 구분한다. 장애 하나에 대응 기록이 여러 개 있을 수 있다.

응답 시각 두 개의 차이를 계산했더라도 그것이 실제 작업 시간인지, 접수부터 완료까지의
경과 시간인지를 구분한다. 근거가 부족하면 지표의 한계를 함께 설명한다.
관측된 원인·메모의 빈도와 실제 인과관계를 구분하고, 일부 조회 결과로 전체 순위를 단정하지 않는다.
