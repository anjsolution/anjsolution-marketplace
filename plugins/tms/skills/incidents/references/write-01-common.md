# 쓰기 작업의 요청 기록과 재시도

이 문서는 현재 구현된 신규 장애 등록에 적용한다. 필수 입력과 오류 코드는 현재 MCP 계약을 따른다.
OAuth 토큰 교환·권한 검증은 MCP와 백엔드가 처리한다. 스킬에서 토큰을 따로 발급하거나 저장하지 않는다.

## 하나의 등록 작업에 하나의 요청 기록

사용자가 요청한 등록 내용이 확정되면 [UUID 생성 스크립트](../scripts/generate_uuid.py)를 한 번 실행한다.
incidents 스킬 폴더를 기준으로 `python scripts/generate_uuid.py`를 실행한다.
작업 디렉터리가 다르면 설치된 스킬의 스크립트 절대경로를 사용한다.
Python 3 표준 라이브러리만 사용하며 UUID v4 하나와 줄바꿈만 출력한다.
출력값을 `idempotency_key`로 사용한다. 재시도 때는 스크립트를 다시 실행하지 않는다.
AI가 UUID 모양의 문자열을 직접 작성하거나 사용자에게 UUID 입력을 요구하지 않는다.

첫 전송 전에 UUID와 실제 도구 입력 전체를 파일로 저장한다. 권장 위치는
`~/.anjsolution/tms/write-requests/<서버별>/<계정별>/<UUID>.json`이다.
서버·계정 구분은 확인된 연결 정보를 사용한다. 플러그인 설치 폴더와 Git 작업 폴더에는 저장하지 않는다.
다른 계정의 작업 기록을 재사용하지 않는다. 작업 파일에는 인증 토큰·비밀번호를 넣지 않는다.
장애 내용이 포함되므로 현재 사용자만 접근하도록 보관한다.

기록에는 작업 종류(`incident.create`), UUID, 실제 입력, 처리 상태, 확인된 성공 결과를 담는다.
UUID는 대화 기억만으로 보관하지 않는다. 생성 스크립트는 파일 저장이나 상태 관리를 하지 않는다.
요청 기록의 저장·복구는 실행 환경의 파일 기능으로 수행한다. 해당 기능을 사용할 수 없다면 자동 보관이
되는 것처럼 진행하지 말고 환경 제약을 알린다.

## 전송과 결과 처리

- 도구 호출에는 저장한 UUID·입력을 그대로 사용한다. 전송 전에 기록을 전송 시도 상태로 남긴다.
- 성공 응답을 받으면 장애 ID·코드 등 결과를 기록하고 완료 처리한다. 완료 기록은 새로 전송하지 않는다.
- timeout·연결 끊김·감사 오류 등 결과가 불명확하면 기록을 유지한다. 재시도는 같은 UUID·입력으로 한다.
  무한 반복하지 않는다. 한 번 재확인해도 불명확하면 사용자에게 상태를 알리고 기록을 보존한다.
- 같은 키에 다른 입력이라는 충돌이 나면 원래 기록을 확인한다. 충돌을 피하려고 새 키로 보내지 않는다.
- 인증·권한 오류는 먼저 원인을 해결한다. 결과가 불명확했던 작업은 권한 복구 뒤에도 같은 기록을 사용한다.
- 입력 수정이 필요하면 기존 요청이 실행되지 않았음이 확인된 경우에만 수정한 내용을 새 작업으로 준비한다.
  결과 불명 상태의 기존 요청은 먼저 해결한다.

사용자가 같은 내용의 별도 장애를 새로 등록하겠다고 명시하면 새 작업과 UUID를 만든다.
입력이 같다는 이유만으로 서로 다른 등록 의도를 합치지 않는다.

## 대화에 보여줄 정보

장애코드·대상·접수일시·상태·요약을 안내한다. UUID·내부 ID는 기본적으로 표시하지 않는다.
문제 추적을 위해 사용자가 요청하면 필요한 식별자를 안내할 수 있다.
결과가 불명확하면 "등록 실패"로 단정하지 않고, 중복 방지를 위해 원래 요청을 유지하고 있음을 설명한다.
