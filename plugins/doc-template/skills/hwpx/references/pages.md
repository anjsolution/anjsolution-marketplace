# 페이지 구성

스크립트는 반복 규칙을 추측하지 않는다. **원본 서식의 페이지를 번호로 골라** 원하는 만큼 넣는다.
어떤 페이지를 몇 번 넣을지는 `pages` 결과와 사용자 요청을 보고 값 JSON 에 적는다.

## 페이지 판별
- 명시적 쪽 나눔(`pageBreak`)을 경계로 본문을 페이지 1, 2, … 로 나눈다(번호는 1부터).
- 이 "페이지"는 원본 서식의 논리 단위다. 내용이 넘쳐 인쇄상 2쪽이 되는 것과는 별개다.
- 경계가 표 안에 있는 등 깔끔하게 나뉘지 않으면 `pages` 가 경고한다(표 안 쪽 나눔은 경계로 쓰지 않는다). 그때는 `xml-edit.md` 로 직접 고친다.
- 구역(section)이 여러 개면 `pages` 구성은 지원하지 않는다. 구역이 여럿인데 `pages` 를 주면 실패하고 XML 직접 편집을 안내한다.

## 값 JSON 규칙
- `pages` 가 없으면 원본 페이지를 순서대로 한 번씩 쓴다.
- `pages` 를 쓸 때는 `{ "page": 정수 }` 항목의 비어 있지 않은 배열이어야 한다. 빈 배열·다른 형태는 실패한다.
- 같은 페이지를 여러 번, 어떤 순서로든 넣을 수 있고 빼도 된다. 서식에 없는 번호는 실패한다.
- 페이지는 언제나 **원본의 그 페이지에서 복사**한다. 앞서 채운 결과를 복사하지 않는다.
- 페이지별 `values` 가 공통 `values` 보다 우선한다. 페이지별 값이 `""`/`null` 이면 공통 값으로 돌아가고, 그래도 없으면 빈칸이다.

## 복사할 때 스크립트가 지키는 것
- 그림·표 객체의 id 는 새로 매긴다(문서 안에서 유일해야 한다).
- 페이지 사이에 쪽 나눔이 정확히 하나씩 들어간다. 마지막 페이지 뒤에는 넣지 않는다.
- 첫 페이지의 복사본에서는 구역 정의(`secPr`)·단 정의(`colPr`)만 제거한다. 구역 설정은 문서에 한 번만 남는다.

## 예시
`pages` 결과가 "페이지 1: 공사명·날짜(표지)", "페이지 2: 사진-1, 내용-1, 사진-2, 내용-2" 라고 하자.

**1. 원본 그대로** — `pages` 를 생략한다.
```json
{ "values": { "공사명": "OO터널", "날짜": "2026-09-17" } }
```

**2. 사진 페이지 반복** — 표지 1번, 사진 페이지를 사진 수만큼.
```json
{
  "values": { "공사명": "OO터널", "날짜": "2026-09-17" },
  "pages": [
    { "page": 1 },
    { "page": 2, "values": { "사진-1": "a.jpg", "내용-1": "전면", "사진-2": "b.jpg", "내용-2": "후면" } },
    { "page": 2, "values": { "사진-1": "c.jpg", "내용-1": "라벨" } }
  ]
}
```

**3. 1쪽만 여러 번** — 같은 양식을 값만 바꿔 여러 장.
```json
{
  "values": { "날짜": "2026-09-17" },
  "pages": [
    { "page": 1, "values": { "공사명": "A터널" } },
    { "page": 1, "values": { "공사명": "B터널" } }
  ]
}
```
