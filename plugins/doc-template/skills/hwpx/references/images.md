# 이미지 규칙

## 인식
- 키 이름에 `사진` 또는 `이미지` 가 들어가면 이미지 자리다. `scan`·`pages` 에 `[이미지]` 로 표시된다.
- 키에 그 단어가 없어도 값이 이미지 파일 경로(`.jpg .jpeg .png .bmp .gif`)면 이미지로 처리한다. 그래서 **설명 칸 값이 확장자로 끝나면 이미지로 오인**된다.
- 이미지 자리인데 값이 이미지 파일이 아닌 문자열이면 글자로 채우고 `이미지 자리에 글자를 넣었습니다` 경고를 낸다. 값 JSON 의 경로·키를 확인해 고친 뒤 다시 만든다.
- 값은 경로 문자열 또는 `{"path": "a.jpg", "width_mm": 80, "height_mm": 60}`. 상대 경로는 값 JSON 파일 위치 기준.

## 크기·배치
- **표 셀 안:** 셀 크기에서 안쪽 여백을 뺀 영역에 비율을 유지한 채 최대 크기로 넣는다(가로 정렬은 아래 정렬 규칙을 따른다). 셀 크기는 바꾸지 않는다.
- **일반 문단:** 본문 폭에 맞추되 높이는 본문 높이의 절반을 넘지 않는다.
- `width_mm`/`height_mm` 를 주면 그 값을 상한으로 비율을 유지한다(둘 다 주면 둘 다 만족하는 최대 크기).
- 토큰이 있던 run 을 그림 객체로 바꾸고, 같은 문단의 나머지 글자는 유지한다.
- 그림은 글자처럼 취급해서 넣는다. 그래서 **가로 정렬은 토큰이 있던 문단의 정렬을 따른다.** 서식에서 토큰 문단을 가운데 정렬해 두면 사진이 가운데에 놓인다. 세로 정렬은 셀의 세로 정렬을 따른다.
- 셀의 `hasMargin="0"` 이면 셀 여백 대신 표의 안쪽 여백을 쓴다.

## 회전(EXIF)
- JPEG 의 EXIF 방향 정보가 있으면 그림 객체의 회전 속성으로 반영한다. 픽셀은 돌리지 않는다.
- 회전된 사진은 `sz` 가 화면에 보이는 크기이고, 회전 각도는 회전 정보·회전 행렬에 담긴다. 한글과 PDF 양쪽에서 똑바로 보이는 것을 확인했다.
- 좌우 반전 값은 반영하지 않고 경고한다.
- 메신저(카카오톡 등)로 받은 사진은 방향 정보가 없는 경우가 많다. 사진이 옆으로 보이면 원본 파일이 그렇게 저장된 것이다.

## 파일 처리
- 원본 이미지를 `BinData/` 에 그대로 넣고 `Contents/content.hpf` 에 등록한다. 원본 파일은 수정하지 않는다.
- 같은 파일을 여러 자리에 넣으면 한 번만 넣고 참조를 공유한다.
- 한 장이 5MB 를 넘으면 경고한다. 자동 축소는 하지 않는다(압축은 이후 manage 스킬).
- 파일이 없거나 지원하지 않는 형식이면 **실패로 멈춘다.** 사진이 빠진 문서가 나가지 않게 한다.
- 이미지 값이 비어 있으면 토큰만 지우고 칸을 비운다.
