# hwpx — 양식에 값·사진 채우기

## 무엇을 하나
`{{필드명}}` 이 적힌 hwpx 양식을 받아 값을 채우고, 사진 자리에는 그림을 넣어 새 hwpx 를 만든다.
원하면 화면 없이 PDF 도 만든다. 원본 양식의 페이지를 골라 여러 번 반복할 수 있다(사진 5장이면 사진 페이지 3개).
양식 원본은 읽기만 하고 절대 고치지 않는다. 결과는 항상 새 파일이다.

> 이 스킬은 **채우기 도구**다. 어떤 템플릿을 쓸지, 어떤 사진이 필요한지 같은 업무 안내는 플러그인 진입점인 `manage` 스킬이 맡는다. TTMS 구축 자료(사진대지 등)는 `manage` 의 가이드를 먼저 보고 이 스킬을 쓴다.

## 실행 방법
```bash
node "${CLAUDE_PLUGIN_ROOT}/skills/hwpx/scripts/hwpx.mjs" <명령> ...
```
Codex 에서는 이 스킬 폴더 기준 상대 경로 `scripts/hwpx.mjs` 로 실행한다.

- 요구사항: Node 18 이상. PDF 출력만 Edge 또는 Chrome 이 필요하다(`CHROME_PATH` 로 지정 가능).
- 첫 실행 때 의존성을 자동 설치한다(1회, 인터넷 필요). 실패하면 종료 코드 3 과 직접 실행할 명령이 나온다.

| 명령 | 하는 일 |
|---|---|
| `scan <서식.hwpx> [--json]` | 토큰 목록(텍스트 / `[이미지]`)·등장 횟수·쪼개진 토큰(`broken`) |
| `pages <서식.hwpx> [--json]` | 쪽 나눔 기준 페이지 목록과 페이지별 토큰, 경고 |
| `fill <서식.hwpx> <값.json> -o <결과.hwpx> [--json]` | 값 채우기 + 페이지 구성 + 사진 삽입 |
| `export <서식.hwpx> <값.json> -o <결과.pdf> [--hwpx <결과.hwpx>] [--json]` | `fill` 결과를 PDF 로. `--hwpx` 를 주면 hwpx 도 저장 |

## 작업 순서
1. **`scan`** — 양식에 어떤 토큰이 있는지, `broken` 이 비어 있는지 본다.
2. **`pages`** — 페이지 구조와 페이지별 토큰을 본다. 어느 페이지가 반복용인지(예: 사진 페이지) 파악한다.
3. **값 JSON 작성** — 사용자 요청과 `pages` 결과로 만든다. 값이 비는 토큰, 사진 파일 경로, 사진 순서는 **사용자에게 확인**한다. 값·경로를 지어내지 않는다.
4. **`fill`**(hwpx 만) 또는 **`export`**(PDF) 실행.
5. **결과 요약을 사용자에게 보고한다.** 아래는 빠뜨리지 않는다.
   - `값 없음` — 빈칸으로 지워진 토큰
   - `서식에 없는 키` — 값 JSON 에 있으나 양식에 없는 키(오타 가능성)
   - `경고` 전부
   - 저장된 파일 경로, 사진이 들어간 위치(`이미지:` 줄)

## 값 JSON
```json
{
  "values": { "공사명": "OO터널 서버 교체", "날짜": "2026-09-17", "모델명": "ABC-100" },
  "pages": [
    { "page": 1 },
    { "page": 2, "values": { "사진-1": "photos/a.jpg", "내용-1": "박스 전체", "사진-2": "photos/b.jpg", "내용-2": "시리얼" } },
    { "page": 2, "values": { "사진-1": "photos/c.jpg", "내용-1": "개봉 후" } }
  ]
}
```
- `values` 는 공통 값. `pages` 가 없으면 원본 페이지를 순서대로 한 번씩 쓴다.
- `pages` 는 `{ "page": 번호 }` 의 비어 있지 않은 목록이다. 같은 페이지를 여러 번, 어떤 순서로든 넣을 수 있다. 페이지는 항상 원본에서 복사한다.
- 페이지별 `values` 가 공통 값보다 우선한다. 페이지별 값이 `""`/`null` 이면 공통 값을 쓰고, 그래도 없으면 빈칸이다.
- 위 예시 셋째 페이지의 `사진-2`·`내용-2` 는 빈칸이 된다(홀수 장).
- 사진 값은 경로 문자열 또는 `{ "path": "a.jpg", "width_mm": 80, "height_mm": 60 }`. 상대 경로는 **값 JSON 파일 위치 기준**.
- 상세: `references/tokens.md`, `pages.md`, `images.md`.

## 실패하거나 경고가 나올 때
종료 코드: `0` 성공 / `1` 실패(원인 메시지가 stderr 에 나옴) / `2` 사용법 오류(`-o`·`--hwpx` 뒤 값 누락 포함) / `3` 의존성 자동 설치 실패.

| 증상 | 조치 |
|---|---|
| `이미지 자리에 글자를 넣었습니다` 경고 | 값 JSON 의 해당 키가 잘못된 경로이거나 이미지가 아닌 값이다. **값 파일을 고쳐 다시 만든 뒤 전달**한다. 그대로 전달하지 않는다. |
| `이미지 파일이 없습니다` 등 실패 | 경로 확인(상대 경로는 값 JSON 기준). 사진이 빠진 문서는 만들지 않는다. |
| `페이지 N 이(가) 서식에 없습니다` | `pages` 결과의 페이지 범위로 다시 지정 |
| `broken`(쪼개진 토큰), `pages` 의 쪽 나눔 경고(표 안), 구역이 여러 개인 서식에 `pages` 구성을 준 `fill`/`export` 실패(`pages` 명령 자체는 목록을 보여준다) | 스크립트로 못 하는 서식이다. `references/xml-edit.md` 절차로 **복사본**을 고친 뒤 진행하고 사용자에게 알린다. |
| PDF 브라우저 없음/기동 실패 | `CHROME_PATH` 지정을 안내하거나 `fill` 로 hwpx 만 만든다. `export --hwpx` 는 PDF 변환 전에 hwpx 경로를 stderr 에 먼저 찍는다. |

## 결과를 줄 때 알려 둘 것
- 공사명·위치·내용 값이 아주 길면 표가 다음 쪽으로 밀려 거의 빈 쪽이 생길 수 있다. 결과 쪽수가 예상보다 많으면 이 점을 알리고 값을 줄이자고 제안한다.
- **값이 `.jpg`/`.jpeg`/`.png`/`.bmp`/`.gif` 로 끝나면 키 이름과 상관없이 무조건 사진으로 삽입된다.** 사진이 아닌 칸(설명·캡션 등)에도 마찬가지이므로 그런 글자 값은 피한다.
- 사진이 옆으로 누워 보이면 원본 파일 자체가 그렇게 저장된 것일 수 있다(메신저로 받은 사진은 방향 정보가 없는 경우가 많다). 스크립트는 방향 정보(EXIF)가 있을 때만 돌린다. 원본을 바로잡아 달라고 안내한다.
- 5MB 넘는 사진은 경고가 나온다. 문서가 커져도 그대로 넣는다.

## 하지 않는 것
- 원본 양식을 수정하지 않는다(복사본만 고친다).
- 사진 압축·리사이즈는 하지 않는다(이후 manage 스킬). 받은 파일을 그대로 넣는다.
- 화면 미리보기는 없다. 확인이 필요하면 PDF 를 만들어 보여 준다.
- 표의 행·표 단위 반복, 구역이 여러 개인 양식의 페이지 구성은 지원하지 않는다.
