# manage — doc-template 진입점

doc-template 플러그인으로 들어오는 요청은 먼저 여기서 받는다. 요청을 보고 **바로 hwpx 스킬로 넘길지**, **업무별 가이드와 함께 진행할지** 정한다.

## 1. 어디로 보낼까

| 요청 | 갈 곳 |
|---|---|
| 양식 파일과 값(사진 경로 포함)이 이미 정해져 있고 채우기만 하면 됨 | `hwpx` 스킬 바로 |
| TTMS 구축 자료(서버 입고·납품 사진대지 등) — 템플릿 선택, 필요한 사진, 순서, 이중화 같은 업무 규칙이 필요함 | 아래 **3. TTMS 구축 자료 제작**의 가이드를 따르고, 채우기는 `hwpx` 스킬 호출 |
| 사진 자체를 알아보는 일(장수·날짜·위치·용량) | **2. 보조 기능** |

업무 규칙이 걸린 요청을 hwpx 스킬로 바로 처리하면 템플릿 선택(단일/이중화), 필수 사진 확인, 사진 순서 같은 설명이 빠진다. 그런 요청은 이 스킬의 가이드를 먼저 읽고 hwpx 를 부른다.

## 2. 보조 기능 (범용)

| 기능 | 문서 | 스크립트 |
|---|---|---|
| 사진 메타데이터 분석 — 촬영 날짜·위치·크기·용량을 폴더 단위로 한 번에 | `references/analyze_image.md` | `scripts/analyze-image.mjs` |

## 3. TTMS 구축 자료 제작 (임시 — TTMS 구축 전용 플러그인으로 이전 예정)

TTMS 구축 전용 플러그인이 생기기 전까지 여기서 관리한다. 관련 문서·스크립트·템플릿은 모두 `ttms_construction_project/` 폴더에 모아 두었고, 이전할 때 폴더째 옮긴다(`references/ttms_construction_project/README.md`). 자료 종류가 늘면 아래에 `3-2`, `3-3` … 으로 추가한다.

### 3-1. 서버 입고(공장 검수)·자재 납품 사진대지

**활용 가이드**
- `references/ttms_construction_project/ttms_photo_doc_make.md` — **사진대지 만들기의 시작점.** 사진 분석·묶기·설명 → 템플릿 선택 → hwpx 스킬로 채우기. 이 문서만으로 바로 시작할 수 있다.
- `references/ttms_construction_project/ttms_photo_doc_types.md` — 사진대지 종류(서버 입고·납품)별 장소, 필수 사진, 촬영 순서, 이중화 터널 규칙, 과거 문서에서 확인한 것
- `references/ttms_construction_project/ttms_photo_doc_location_data.md` — 현장 사진의 GPS·촬영 시각으로 방문 목록을 만들고 설치 장소(관리동·지사·본부·○○청 서버실 등)를 확인받기

**템플릿** (`templates/ttms_construction_project/`, 목록·입력 키는 폴더 안 `README.md`)
- 서버 입고 사진대지 — 단일 / 이중화(`_dual`)
- 자재 납품 사진대지 — 단일 / 이중화(`_dual`)

**제공 예정**
- 설치 장소(관리동·지사·본부·○○청 서버실 등) 등록·위치 검토·좌표/주소 채우기
- 사진촬영용 서버 납품 정보 종이 템플릿

## 공통 원칙
- 원본 파일(사진·양식)은 읽기만 한다. 결과는 항상 새 파일이다.
- 위치(GPS)는 민감 정보다. 사용자가 요청하지 않으면 문서에 넣지 않는다.
- 명칭·규칙을 바꿔야 할 일이 생기면 바로 고치지 말고 저장소에 이슈 등록을 안내한다.
