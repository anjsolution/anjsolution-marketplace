# 사진 메타데이터 분석 (analyze-image)

## 언제 쓰나
- 사진대지를 만들기 전에 사진 몇 장이 있고 언제 찍었는지, 크기·용량이 얼마인지 알아야 할 때
- 촬영 순서로 사진을 정렬하거나, 날짜·위치가 들어 있는 사진을 가려낼 때
- "사진 용량이 큰 게 있나", "촬영 날짜가 있는 사진만 골라줘" 같은 요청

사진은 읽기만 한다. 파일을 고치거나 이름을 바꾸지 않는다.

## 실행 방법
```bash
node "${CLAUDE_PLUGIN_ROOT}/skills/manage/scripts/analyze-image.mjs" <경로> [<경로> ...] [--list <목록.txt>] [--recursive|-r] [--json]
```
Codex 에서는 이 스킬 폴더 기준 상대 경로 `scripts/analyze-image.mjs` 로 실행한다.

- 요구사항: Node 18 이상. 설치할 것이 없다(Node 기본 기능만 사용).
- 사진 파일의 앞부분(헤더)만 읽어서 수십 장도 1초 안에 끝난다.

## 입력
- `<경로>` 는 사진 파일 또는 폴더이고, 여러 개를 섞어 줄 수 있다. 폴더는 그 안의 사진 파일 전부이며, 하위 폴더는 `--recursive`(`-r`)를 줄 때만 들어간다(폴더의 사진 → 하위 폴더 이름순). `--list` 안의 폴더에도 같이 적용된다.
- `--list <목록.txt>` 는 한 줄에 경로 하나인 텍스트 파일(UTF-8). 빈 줄과 `#` 로 시작하는 줄은 무시한다. 상대 경로는 목록 파일 위치 기준이다.
- 사진 확장자: `.jpg .jpeg .png .gif .bmp .heic .heif` (대소문자 무시). 그 밖의 파일은 건너뛴다.
- 없는 경로는 stderr 로 알리고 나머지는 계속 처리한다.

## 출력
기본은 사진마다 한 줄이다.
```
파일명 | 1440×1080 | 523KB | 촬영 2024-12-12 15:27:27 | 위치 37.12345,128.12345 | 기기 samsung SM-S918N
```
끝에 요약이 붙는다: 총 장수, 촬영 날짜 있음, 위치 있음, 촬영 기간(최초~최후), 읽기 실패.
정렬은 촬영 일시가 있는 사진을 촬영순으로 먼저, 없는 사진은 입력 순서대로 뒤에 둔다.

`--json` 은 `{ "photos": [...], "summary": {...} }` 를 낸다. 사진마다 항목은 다음과 같다.

| 항목 | 값 | 없을 때 |
|---|---|---|
| `file` | 절대 경로 | — |
| `bytes` | 파일 크기(바이트) | — |
| `width`, `height` | 저장된 픽셀 크기 | `null` |
| `orientation` | EXIF 방향 값(1~8) | `null` |
| `taken_at` | 촬영 일시 `YYYY-MM-DD HH:MM:SS` (시간대 정보가 있으면 `+09:00` 이 붙음) | `null` |
| `gps` | `{ lat, lon, alt }` 십진수(남위·서경은 음수) | `null` |
| `device` | `제조사 모델` | `null` |
| `format` | jpg / png / gif / bmp / heic | — |
| `error` | 읽기 실패·미지원 사유 | 항목 없음 |

`summary` 는 `total, withDate, withGps, from, to, failed`.

종료 코드: `0` 성공(일부 사진이 읽기 실패여도 결과에 표시하고 0) / `1` 입력 경로가 전부 없음 / `2` 사용법 오류.

## 결과 읽는 법
- **`null`(사람용 출력의 "없음")은 사진에 그 정보가 없다는 뜻이다.** 파일 이름이나 수정 시각으로 날짜를 추측하지 않는다. 그대로 "없음"이라고 전달한다.
- 카카오톡·메신저로 받은 사진은 촬영 날짜·위치가 지워져 있는 경우가 대부분이다. 모두 "없음"으로 나오면 이 때문일 가능성이 높다. 날짜·위치가 필요하면 원본(카메라에서 직접 복사한 파일)을 받거나, 카카오톡에서 **"원본으로 보내기"** 로 다시 받도록 안내한다.
- 파일 이름에 날짜가 있어도(예: `KakaoTalk_20241212_...`) 그것은 받은 시각일 뿐 촬영 시각이 아니다. 메타데이터 값과 구분해서 말한다.
- `width`×`height` 는 저장된 픽셀 크기이고, `orientation` 이 6·8 이면 화면에는 가로·세로가 바뀌어 보인다.
- HEIC/HEIF 는 아직 분석하지 않는다(`format: heic`, `error` 표시, 크기·날짜 `null`). 필요하면 JPEG 로 변환된 파일을 요청한다.
- PNG·GIF·BMP 는 크기만 읽는다(날짜·위치·기기는 항상 없음).
- 읽기 실패(`error`)가 있는 사진은 사용자에게 파일명과 사유를 알린다.

## 주의
- **위치(GPS)는 민감 정보다.** 결과로 보여 주기만 하고, 사용자가 요청하지 않으면 문서·값 JSON 에 넣지 않는다. 결과를 다른 곳에 공유하자는 제안도 하지 않는다.
- 이 스크립트는 읽기 전용이다. 사진을 고르거나 정렬한 결과를 파일로 저장하려면 사용자 요청이 있을 때 별도 파일로 만든다.
- 분석 결과를 hwpx 사진대지에 쓰려면 `hwpx` 스킬로 넘어가고, 사진 순서·선택은 사용자에게 확인한다.
